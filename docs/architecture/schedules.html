Schedules, reminders and recipes

Start work or send a message on a timer, or save a job that comes up again.

A tick

What a schedule can start

Key states

enabled
Checked every tick.
skipped
Not run this time; the reason is kept.
caught up
A missed run happened late, once.
failed
Could not start; noted in the orchestrator's chat and on your phone, once per streak.
done
A one-off that has run.

In plain words

A dev server runs no schedules unless told to, so a second copy never doubles them. Removing a schedule keeps its history.

Recipes are also what the orchestrator's run_recipe runs.

Key files

  • lib/schedules/scheduler.ts the ticker
  • lib/schedules/run.ts running one schedule
  • lib/schedules/start.ts starting tasks and sessions
  • lib/schedules/cron.ts cron times
  • lib/recipes saved recipes
  • lib/orchestrator/reminders.ts the orchestrator's reminders
