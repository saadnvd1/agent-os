Tasks and the queue

Work that ends in a pull request: queued by priority, held for load, started in its own worktree, gated, merged and deployed.

A task, start to deploy

Why a queued task is waiting

Key states

running
Task status while it is alive. Ends as merged, dropped, done, moving or moved.
working
The agent is going, or its worktree is being set up.
needs-input
Idle and not waiting on a gate or an ask.
blocked
A BLOCKED: line, or it waits on an approval or a question.
review
PR open, checks passing, waiting on gates and sign-off.
checks-failing
PR open and CI failing.
plan-ready
A plan is written and waits for approval.
exited
The session is gone.
merged
Merged through the gates.
dropped
Rejected: PR closed, everything removed.
done
Finished and put on the Done shelf.
moving
Being handed to another machine.

In plain words

A queued row is a database row: nothing is on disk until it starts, and the line survives a restart. A task started with room to spare goes straight to a worktree. A workspace can cap how many run at once, and what is over the cap waits under Queued.

A running task can be paused for an hour, two, until tomorrow morning or until resumed. It gives its slot away and, on resuming, goes ahead of new arrivals of the same priority.

Agents never merge their own work. Merging goes through the gates, either when an armed PR passes or when someone signs it off.
