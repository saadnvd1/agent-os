Sessions and chat workers

A chat runs in a worker process of its own, so a restart of AgentOS never ends a conversation.

Key states

running
Activity within the cooldown. Green.
waiting
Cooldown over and you haven't looked yet: it needs attention.
idle
Cooldown over and you've seen it.
dead
The session is gone.

In plain words

A chat and a terminal are two views of the same kind of session. A chat's agent turn lives in a worker, a separate process in its own tmux session named aos-chat-<id>, so the server can restart under it. The worker and the server speak newline-delimited JSON over a local socket.

Each message carries an id, so one sent twice (a retry after a dropped socket) is taken once. Commands the server can send a worker include send, send_now (stop the running turn for a queued message), drain, interrupt, background_task, retire, fresh and close.

Backgrounding a running step hands it to the worker, and the messages queued behind it are sent.

Key files

  • lib/chat/runner.ts worker lifecycle: ensure, retire, reattach, resume
  • lib/chat/worker/protocol.ts every command and event between server and worker
  • lib/chat/worker/host.ts the worker process itself
  • lib/chat/socket.ts the chat WebSocket
  • lib/chat/store.ts stored items
  • lib/chat/queue.ts queued messages
  • lib/status-detector.ts terminal status
