When main moves, the running instance is rebuilt and restarted, and the same commit is published, without cutting work off.

Key states

deployed
The head last built and restarted.
published
The head last sent to npm.
held
A newer head is waiting out the restart gap.

In plain words

State is a handful of small files (deployed head, published head, last restart time, the head currently held, the head already warned about) and two lock directories; a lock older than 30 minutes is treated as from a run that died.

The times are settings of the job: settle 120 s, restart gap 3600 s, quiet wait 600 s.

Key files

  • scripts/autodeploy the job
  • scripts/wait-quiet waits for in-flight work
  • scripts/redeploy build, swap, restart, rollback
  • scripts/publish npm publish
  • app/api/busy what counts as in flight
